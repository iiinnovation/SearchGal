# Windows 安装与交互验收

目标为 Windows 10 / 11 x64。构建成功、macOS 测试通过、Windows CI 测试通过和干净 Windows 实机验收分别记录，不能相互替代。构建和测试方法见 [桌面端说明](README.md)，发布时应记录该版本的实际验收结果。

## 安装包自动验收

在一次性 Windows 测试账户或虚拟机中执行，先关闭其他 SearchGal。测试脚本会安装并卸载应用，已有 SearchGal 安装、进程或同名快捷方式时拒绝执行。此环境需要 Node.js 24 和桌面端测试依赖，因此不属于“未安装开发环境”的验收。

```powershell
cd desktop
npm ci
npm run build
npm test
npm run test:e2e
npm run dist:win
./scripts/verify-windows-install.ps1 -Installer ./release/SearchGal-Setup-0.1.0-x64.exe
```

脚本执行当前用户静默安装，安装路径包含中文和空格；检查桌面与开始菜单快捷方式指向安装后的 `SearchGal.exe`，用该程序运行 Electron 测试，最后卸载并检查程序及快捷方式消失。测试断言 `app.isPackaged`、实际可执行文件位置和独立数据目录，覆盖下载续传、后台下载、分卷缺失与重试、异常退出恢复、取消、设置持久化和用户图片导入。

安装步骤结果及安装包 SHA-256 写入 `verification/windows-install/result.json`，界面测试截图、状态快照与报告写入 `test-results-installed/`。Windows Actions 工作流也调用此脚本并上传记录；工作流尚未执行时，这些步骤仍为待验。

也可以对已经安装的程序单独运行测试：

```powershell
$env:SEARCHGAL_TEST_EXECUTABLE = 'C:\你的安装目录\SearchGal.exe'
npm run test:e2e
Remove-Item Env:SEARCHGAL_TEST_EXECUTABLE
```

测试只在临时目录保存数据和生成的下载文件。安装版支持 `--user-data-dir=<绝对路径>` 指定独立配置目录；不传此参数时仍使用正常用户数据目录。

## 干净系统与人工交互

准备没有 Node.js、npm、Wrangler 或 aria2 的 Windows 测试机；只复制安装包，不复制源码或 `node_modules`。Windows 10 与 11 的记录分开填写，注明系统版本、显示器布局、缩放比例、安装包 SHA-256 和测试时间。

| 项目 | 操作与通过条件 | 状态 |
| --- | --- | --- |
| 安装 / 卸载 | 普通用户通过安装向导选择中文带空格路径；快捷方式可启动；卸载移除程序与快捷方式，保留下载文件和配置 | 待验 |
| 独立启动与搜索 | 从快捷方式启动；不启动 API；搜索完成并展示真实平台候选；记录站点错误与候选数量 | 待验 |
| 下载目录与打开文件夹 | 使用系统目录对话框选择中文路径；完成后“打开文件夹”定位到实际文件夹 | 待验 |
| 下载控制 | 使用自有或明确授权的小文件；手动选源、失败回退、暂停、继续、取消；检查实际文件内容 | 待验 |
| 分卷完整性 | 必需分卷缺失不能显示完成；补齐后重试，解压并核对内容 | 待验 |
| 关闭面板与托盘 | 关闭或隐藏面板后下载继续；实际点击托盘恢复面板；托盘退出保存并暂停；再次启动可恢复 | 待验 |
| 异常退出 | 任务管理器结束主进程后重启，任务暂停，继续后文件完整；取消任务不自动重启 | 待验 |

| 多屏 / 缩放 | 100%、150%、200% 缩放下操作面板；跨屏、拔除副屏，窗口仍可访问 | 待验 |

目录对话框在自动测试中使用返回值替身；托盘菜单、资源管理器、系统通知、透明区域点击穿透和物理多屏必须按表人工验证。角色素材交接前不要把桌宠交互列为通过，也不要使用临时角色代替默认角色。
