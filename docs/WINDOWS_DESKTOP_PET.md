# Windows 桌面宠物方案建议

调研日期：2026-09-07。本文保留设计方案，当前功能与构建方法见 [桌面端说明](../desktop/README.md)。已完成的 downloader 修复不等于桌面版已经完成或通过 Windows 验收。

## 参考项目：Confirmo

用户提到的 yetone 项目是 [Confirmo](https://confirmo.love/)，定位为桌面 AI 编程伴侣。本次查看了官网、公开发行记录和角色图库，没有安装或实测其 Windows 应用。

- [公开发行页](https://github.com/yetone/confirmo-releases/releases/tag/v1.0.96) 提供 Windows `setup.exe`，以及 macOS、Linux 包；该版本于 2026-05-18 发布。
- 发布记录包含 Claude Code / Codex 任务状态、完成动画、需要用户处理时的提醒，以及托盘、位置记忆、角色大小、透明区域点击穿透。
- 自定义角色以二维精灵图动画为基础：[v1.0.12](https://github.com/yetone/confirmo-releases/releases/tag/v1.0.12) 增加自定义 sprite sheet，[v1.0.54](https://github.com/yetone/confirmo-releases/releases/tag/v1.0.54) 支持多个自定义角色并记住选择；另有 [角色图库](https://sprites.confirmo.love/)。
- [v1.0.91](https://github.com/yetone/confirmo-releases/releases/tag/v1.0.91) 记录了读取 Codex 自定义宠物目录的支持。
- 发布记录明确提及 Electron，发行包的构建配置也有 electron-vite / electron-builder 痕迹。公开的 `confirmo-releases` 主要存放发行信息，未找到完整应用源码或明确的源码复用许可证；本方案借鉴其交互，自行实现并使用原创或明确授权素材。

## 建议的首版体验

用户安装一个 Windows 应用，启动后出现桌面角色。搜索与下载在应用内部运行，用户无需安装 Node.js、pnpm、Wrangler，也无需手动启动本地 API。

| 场景 | 桌宠与界面的行为 |
| --- | --- |
| 空闲 | 轻量待机动作；可拖动、缩放、记住位置；可隐藏到托盘 |
| 搜索 | 点击角色展开搜索框，输入游戏名，展示平台与资源候选 |
| 下载 | 角色进入工作动作，小气泡显示实际进度；详细面板管理任务 |
| 来源失败 | 显示正在切换来源；全部失败时提供重试或打开来源页面 |
| 完成 | 所有必需分卷完成后播放完成动作，提供打开下载目录按钮 |
| 自定义 | 设置中切换角色、导入素材、修改大小和提示语、控制音效 |

宠物动作由任务状态驱动，首版的搜索和下载不依赖用户配置 AI 聊天模型。已有下载逻辑只证明文件下载完成；未经归档校验时，界面不能显示“解压验证通过”。

## 默认角色与自定义

建议先内置 3 个原创 Q 版二次元角色，例如猫耳少女、魔法少女、机器人少女，使用统一的动作规范：待机、搜索、下载、完成、出错。具体外形为待设计建议，当前没有生成或引入这些角色素材。

首版优先采用透明二维图片及精灵图动画：

- 普通用户可以导入一张透明图片，使用呼吸、轻微晃动等基础动作。
- 进阶用户可以导入包含各状态动画的角色包，预览后保存；角色包只包含素材和声明式配置。
- 单张插画不会自动获得完整的走路、挥手动作；这些效果需要对应动画素材。
- 为渲染器预留扩展接口。Live2D 可作为后续选项，用于更细致的头发、表情和身体动作；Live2D 模型需要拆图及绑定，不能等同于普通 PNG。当前未承诺兼容任意第三方角色包。

## 实现路线

建议采用 Electron + React / TypeScript。Electron 自带运行时，适合复用现有 TypeScript 搜索和 Node 下载代码，并生成 Windows 安装包；代价是安装体积和基础内存占用较大。

应用分为透明桌宠窗口、搜索与任务面板、后台任务进程。动画和界面运行在渲染进程，搜索、文件写入和下载运行在后台进程，通过结构化消息更新状态。透明区域点击穿透与角色拖拽须分别处理。

当前代码可以复用，但需要以下适配：

1. 将 `src/core.ts` 的平台搜索逻辑封装为本地服务；Cloudflare 的 `waitUntil` 包装不直接作为桌面入口。保留可配置远程 SearchGal API 的能力。各平台在 Electron 的 Node 环境中需要重新验证。
2. 将 `downloader/src/core/Harness.ts` 中的终端交互与编排分离。界面通过任务事件接收搜索结果、选源、下载进度、失败和完成状态，不解析控制台文本。
3. 为下载工具补充进度回调、调用方取消信号和任务记录。现有断点文件可作为恢复基础，但目前没有完整的界面暂停 / 恢复接口；实现时必须保留来源、ETag、范围和完整大小校验。
4. 默认使用内置 Node 下载器，安装包不依赖系统预装 aria2。若首版包含 BT，需额外打包 Windows aria2 并验证其进程管理、续传和分发条件。
5. 下载目录和角色素材由系统对话框选择，配置与任务记录保存在用户数据目录。关闭桌宠显示与退出应用须有清楚区别，避免误中断下载。

## 建议的交付顺序

1. 跑通 Windows 应用中的搜索、选源、下载、进度和取消；后台服务由应用管理。
2. 加入透明桌宠、3 个默认角色、导入预览和状态动作，完成一个可用的产品闭环。
3. 在未安装开发环境的 Windows 机器上验收安装包，再交付给普通用户。

Windows 验收应覆盖中文路径、多显示器与缩放、透明区域点击穿透、拖拽、托盘退出、暂停与恢复、候选切换、分卷完整性以及异常退出后的任务恢复；继续运行现有下载回归测试。首版目标为 Windows 10 / 11 x64，实际支持范围以对应环境的测试结果为准。
